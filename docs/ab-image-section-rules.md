# playready A문서/B문서 이미지 섹션 규칙표

> 이 문서는 A문서와 B문서에 이미지를 언제 넣고, 언제 넣지 말아야 하는지 먼저 고정하기 위한 기준표입니다.
> 핵심 원칙은 간단합니다.
>
> - 이미지가 텍스트 이해를 분명히 도와줄 때만 넣습니다.
> - 이미지가 텍스트와 직접 맞지 않으면 넣지 않습니다.
> - "이미지가 있으니 일단 넣는다"는 금지합니다.
> - "정확히 맞는 이미지가 없으면 텍스트만 간다"를 기본값으로 둡니다.

---

## 1. 먼저 이해할 기본 원칙

### 1-1. 이미지 사용의 기본값

- 기본값은 `이미지 없음`입니다.
- 아래 조건을 만족할 때만 이미지를 넣습니다.
  - 해당 섹션의 핵심 내용을 시각적으로 더 빨리 이해할 수 있어야 함
  - 이미지가 본문 문장과 직접 연결되어야 함
  - 캡션이 짧고 명확하게 붙을 수 있어야 함
  - 같은 이미지를 억지로 반복 사용하지 않아야 함

### 1-2. 이미지를 넣지 말아야 하는 공통 경우

- 본문과 무관한 일반 페이지 이미지
- 같은 이미지가 여러 섹션에 반복될 때
- 캡션을 붙여도 왜 들어갔는지 설명이 안 되는 이미지
- 작은 아이콘 하나를 과하게 확대해서 오히려 읽기 어려운 경우
- 페이지 전체 이미지를 잘라내지 않고 그대로 붙여 여백이 너무 큰 경우
- "행동 흐름"을 설명하는데 실제로는 행동과 무관한 보드/장식 이미지인 경우

### 1-3. 캡션 원칙

- 캡션은 반드시 짧게 씁니다.
- 좋은 캡션 예시
  - `룰북 3페이지 | 시작 세팅 예시`
  - `룰북 6페이지 | 개인 보드 예시`
  - `FAQ 1페이지 | 수정된 아이콘 설명`
- 나쁜 캡션 예시
  - `이 이미지는 플레이어가 행동을 하는 모습을 보여줍니다`
  - `다음과 같은 보드를 참고하면 됩니다`
  - 깨진 문자나 긴 문장형 캡션

### 1-4. 이미지 우선순위

이미지를 꼭 하나만 살려야 한다면 아래 순서로 우선합니다.

1. 실제 셋업/보드 상태를 이해시키는 이미지
2. 구성물 구분을 명확히 해주는 이미지
3. 아이콘 의미를 직접 설명하는 이미지
4. 예외 규칙이나 FAQ에서 수정된 도해
5. 단순 장식 이미지

즉, 장식 이미지는 사실상 가장 먼저 빠져야 합니다.

## 2. 문서 A 이미지 규칙

문서 A는 `혼자 공부하는 학습용 문서`입니다.
즉, 이미지는 "예쁘게 보이기 위한 장식"이 아니라 "이해를 돕는 참고 자료"여야 합니다.

### A문서 공통 원칙

- A문서는 텍스트 이해가 먼저입니다.
- 이미지는 "이 섹션을 텍스트만으로 읽었을 때 헷갈릴 수 있는 부분"을 보조할 때만 넣습니다.
- 이미지가 있다면 섹션 하단 참고 블록으로 넣고, 본문 한가운데를 끊지 않습니다.
- 한 섹션에 이미지가 너무 많으면 오히려 학습 흐름이 깨지므로, 보통 1~2개를 넘기지 않습니다.

## 3. A문서 섹션별 규칙표

| A문서 섹션 | 이미지 허용 여부 | 넣어도 되는 이미지 | 넣으면 안 되는 이미지 | 판단 기준 |
| --- | --- | --- | --- | --- |
| 1. 게임 개요 | 원칙적 금지 | 게임의 핵심 보드 한 장, 전체 분위기를 이해시키는 대표 이미지 1장만 예외 허용 | 구성물 세부 이미지, 아이콘 확대, 무관한 장식 이미지 | 이미지 없이도 개요 설명이 되면 넣지 않음 |
| 2. 플레이어 턴 흐름도 | 기본 금지 | 실제 턴 순서를 이해하는 데 꼭 필요한 행동 순서 도해, 선택지 위치가 분명한 보드 일부 | `행동 위치 참고 이미지`처럼 왜 필요한지 설명되지 않는 일반 보드 이미지 | 흐름도만으로 이해 가능하면 이미지 제외 |
| 3. 핵심 행동 상세 설명 | 조건부 허용 | 해당 행동과 직접 연결되는 행동 칸/작업 칸/선택지 도해 | 전체 페이지 캡처, 다른 행동과도 구분 안 되는 일반 보드 이미지 | 행동 설명과 이미지가 1:1로 연결될 때만 |
| 4. 게임 준비와 시작 상태 | 적극 허용 | 셋업 완료 예시, 공용 준비 상태, 플레이어 시작 상태 예시 | 장식 그림, 세팅과 무관한 페이지 전체 이미지 | 준비 순서를 시각적으로 줄일 수 있으면 허용 |
| 5. 자원·보드·트랙·상태 연결 | 조건부 허용 | 트랙 위치, 자원 칸, 점수 트랙 등 연결 구조를 보여주는 이미지 | 단순 삽화, 읽어도 무슨 트랙인지 모호한 이미지 | "이 자원이 어디에 쓰이는지"를 더 빨리 보여줄 수 있을 때만 |
| 6. 라운드 종료와 게임 종료 | 원칙적 금지 | 종료 체크 위치, 종료 트리거 표시 등 꼭 필요한 표식 이미지 | 일반 보드 이미지, 종료와 무관한 장식 | 종료 규칙이 위치/표식과 강하게 연결된 경우만 허용 |
| 7. 점수/승리 조건 이해 | 조건부 허용 | 점수 트랙, 점수 계산 예시, 최종 점수 관련 보드 구간 | 구성물 사진, 셋업 이미지 | 점수 설명이 숫자/위치와 강하게 연결될 때만 |
| 8. 헷갈리기 쉬운 규칙 정리 | 조건부 허용 | FAQ/정오표에서 수정된 도해, 오해가 자주 생기는 규칙 예시 그림 | 관련 없는 반복 이미지 | FAQ에 공식 도해가 있을 때만 |

## 4. A문서 조건부 섹션 규칙표

| A문서 조건부 섹션 | 이미지 허용 여부 | 넣어도 되는 이미지 | 넣으면 안 되는 이미지 | 판단 기준 |
| --- | --- | --- | --- | --- |
| 구성물 해설 | 적극 허용 | 공용 구성물, 개인 구성물, 구성물 도해 | 게임 분위기 삽화, 페이지 전체 캡처 | 구성물 구분이 실제로 헷갈릴 때만 |
| 아이콘/기호 사전 | 적극 허용 | 아이콘 원본, FAQ 수정 아이콘, 아이콘 묶음 카드 | 아이콘과 무관한 보드 이미지 | 아이콘 게임일 때만 섹션 생성 |
| 보드/개인판 구조 설명 | 적극 허용 | 메인 보드, 개인 보드, 영역 구분 도해 | 단순 장식 이미지 | 실제 플레이 이해에 보드 구조가 중요할 때만 |
| 목표/임무/카드 시스템 | 조건부 허용 | 카드 예시, 목표 예시, 공개/비공개 구분 예시 | 일반 보드 이미지 | 카드 시스템이 게임 핵심일 때만 |
| 플레이어 간 상호작용 | 조건부 허용 | 경쟁 칸, 공유 자원, 순서 경쟁 등 직접 관련 이미지 | 분위기 삽화 | 상호작용이 위치/보드 구조와 연결될 때만 |
| 특수 모드 | 조건부 허용 | 1인 모드 전용 보드, FAQ 수정 도해 | 일반 본게임 이미지 반복 | 특수 모드 자료가 실제로 있을 때만 |

## 5. 문서 B 이미지 규칙

문서 B는 `다른 사람에게 설명할 때 쓰는 보조 자료`입니다.
즉, 이미지는 "말할 때 바로 보여주기 쉬운 요약 자료"여야 합니다.

### B문서 공통 원칙

- B문서는 짧고 빠르게 보여줘야 하므로 이미지 수를 더 적게 가져갑니다.
- B문서에서는 "한 장으로 바로 이해되는 이미지"가 아니면 과감히 뺍니다.
- 설명자가 말하면서 가리킬 수 있는 이미지여야 합니다.
- 한 섹션에 여러 이미지를 붙이는 것보다, 한 장의 정확한 이미지가 더 낫습니다.

## 6. B문서 섹션별 규칙표

| B문서 섹션 | 이미지 허용 여부 | 넣어도 되는 이미지 | 넣으면 안 되는 이미지 | 판단 기준 |
| --- | --- | --- | --- | --- |
| 1. 30초 소개 멘트 | 원칙적 금지 | 게임 전체 분위기를 보여주는 대표 이미지 1장만 예외 허용 | 구성물 사진, 보드 세부 이미지 | 설명 첫 줄에서 꼭 필요하지 않으면 넣지 않음 |
| 2. 플레이어 턴 흐름도 (간소화) | 기본 금지 | 흐름을 직접 도와주는 간단한 보드 일부, 선택지 위치 표시 이미지 | 일반 보드 전체 이미지, 행동과 무관한 장식 이미지 | 흐름도만으로 충분하면 이미지 제외 |
| 3. 핵심 행동 요약 | 조건부 허용 | 행동 칸/선택지 위치를 한눈에 보여주는 이미지 1장 | 세부 도해 여러 장, 섹션과 무관한 반복 이미지 | 행동 설명이 위치와 강하게 연결될 때만 |
| 4. 첫 라운드 설명 스크립트 | 적극 허용 | 첫 라운드 시작 상태, 시작 배치, 초기 행동 위치 예시 | 일반 삽화, 점수 관련 이미지 | 실제로 설명자가 "여기 보세요" 하고 가리킬 수 있을 때만 |
| 5. 자주 헷갈리는 질문 | 원칙적 금지 | FAQ 도해가 공식적으로 있을 때만 예외 허용 | 일반 참고 이미지 전체 | 텍스트 답변이 더 빠르면 이미지 금지 |
| 6. 라운드 종료 / 게임 종료 체크리스트 | 원칙적 금지 | 종료 체크 위치, 종료 조건 표시 구간 | 관련 없는 보드/구성물 이미지 | 종료 트리거가 위치 기반일 때만 예외 허용 |
| 7. 용어 / 참조 카드 | 기본 금지 | 아이콘 참조 카드, 아주 짧은 용어 도해 | 큰 보드 이미지, 중복 이미지 | 빠른 참고에 도움이 될 때만 |

| 모드별 보충 설명 | 조건부 허용 | 1인 모드/팀전/캠페인 차이를 보여주는 공식 예시 | 일반 본게임 이미지 반복 | 별도 모드 규칙이 실제로 있을 때만 |

## 8. 절대 넣지 말아야 하는 조합

아래 조합은 기본적으로 금지합니다.

| 잘못된 조합 | 이유 |
| --- | --- |
| 흐름도 섹션 + 일반 보드 전체 이미지 | 흐름 설명과 직접 연결되지 않음 |
| 긴 설명 섹션 + 의미 불명 이미지 여러 장 | 읽는 흐름만 끊고 이해에는 도움 안 됨 |
| A문서와 B문서에 같은 이미지 반복 삽입 | 문서 목적 차이를 흐림 |
| 아이콘 섹션이 아닌데 아이콘 카드 삽입 | 독자가 왜 있는지 이해 못 함 |
| 캡션 없이 이미지 삽입 | 이미지 사용 이유를 설명하지 못함 |
| 깨진 문자 포함 캡션 | 완성도 저하, 신뢰도 하락 |

## 9. 이미지 삽입 결정 순서

코드에서 이미지를 붙일 때는 아래 순서대로 판단하는 것이 좋습니다.

1. 현재 섹션이 이미지 허용 섹션인가?
2. 해당 섹션에 맞는 종류의 이미지가 실제로 있는가?
3. 그 이미지가 본문과 1:1로 연결되는가?
4. 짧은 캡션을 붙여도 자연스러운가?
5. 같은 이미지가 앞서 이미 쓰이지 않았는가?
6. 위 5개 중 하나라도 아니면 넣지 않는다.

즉, 마지막 기본 원칙은 이것입니다.

**의심되면 넣지 않는다.**

## 10. 이후 코드 반영 시 바로 써먹을 구현 규칙

### 10-1. 기본 정책

- 이미지 정책 기본값: `omit`
- 특정 섹션만 `allow`
- 아주 일부 섹션만 `prefer`

### 10-2. 섹션별 정책 예시

- 문서 A
  - `게임 개요`: omit
  - `플레이어 턴 흐름도`: omit
  - `게임 준비와 시작 상태`: prefer
  - `구성물 해설`: prefer
  - `아이콘/기호 사전`: prefer
  - `헷갈리기 쉬운 규칙 정리`: allow

- 문서 B
  - `30초 소개 멘트`: omit
  - `플레이어 턴 흐름도 (간소화)`: omit
  - `핵심 행동 요약`: allow
  - `첫 라운드 설명 스크립트`: prefer
  - `자주 헷갈리는 질문`: omit
  - `셋업 체크리스트`: prefer

### 10-3. 이미지가 없을 때 동작

- 이미지가 없으면 섹션은 텍스트만 유지
- "이미지 없음" 문구도 굳이 넣지 않음
- 빈 이미지 섹션 자체를 만들지 않음
